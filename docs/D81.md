# D81 / 1581 build

`make boot` now emits D64, D71 and **D81** under `build/boot/`. D81 is a
standard 819,200-byte Commodore 1581 image: 80 logical tracks, 40 sectors per
track, 256 bytes per sector. The header is at 40/0, two BAM sectors at 40/1–2,
and directory at 40/3. File types, names and exact byte streams are preserved
from the D71, while allocation maps and sector links are rebuilt.

The native C128 BOOT reader advances this payload using **21 sectors per track
even with a 1581**. `tools/build_d81.py` preserves its track/sector addresses,
not the D71 byte offsets or a linear 40-sector copy. These raw boot sectors
are marked occupied in the BAM; normal files can use the remaining sectors.

The read-only IEC service detects geometry from volume headers on each open.
It supports all 296 D81 directory slots, tracks through 80, sectors through 39,
bounded file chains, and free-space counts from both BAMs. `df` excludes the
directory track, reporting 3,160 total data blocks. Device 8 still mounts at
`/`; suffix mapping, `/etc/rc`, ordinary programs and `/mnt` are unchanged.

## Test

Use a fresh VICE C128 with a **1581** on device 8. Attach
`build/boot/udeks.d81`; cold-start or type `BOOT` from BASIC. Confirm `ls /bin`,
`df`, `cat /etc/rc`, and graphical launches. For the independent SDK examples,
use `build/generic-apps/apps-demo.d81` and the [SDK test sequence](GRAPHICAL-APPS-SDK.md).

### 1986

D81 needs a **1581**, not a 1571 with a different disk attached. In 1986:

1. Select **Media → 1581 (D81, ROM required)** for device 8.
2. Enable **Advanced → Real Disk Drive** and supply `roms/dos1581.bin`
   (32 KiB; `dos1581-318045-02.bin` is also recognized).
3. Restart 1986 so the selected drive model takes effect, attach the D81,
   and boot from a fresh C128 session.

An existing `drive_type = 1571` setting is not automatically changed by attaching
a D81. The regression harness now configures the actual IEC drive model before
power-on, matching the desktop path, and rejects disk/drive mismatches.
Unmodified 1986 revision `81485cc7` passes native D81 boot, disk commands,
two native clocks, native keyboard/1351 drag/close, four-window coexistence,
and running-panel text/attributes with a ROM-backed 1581. This is emulator
qualification, **not physical 1581 acceptance**. Evidence:
`bench/results/2026-10-04-app-panel`.

```sh
distrobox enter my-distrobox -- python3 tools/1986_storage_smoke_build.py \
  --emulator ../1986 --roms ../1986/roms --native-clock \
  --disk build/boot/udeks.d81 --drive 1581 \
  --output build/native-clients/1986-d81
```

Automated gates: `make check`, container `make graphics-apps-check placement-check`,
host `make console-apps-probe`, and:

```sh
python3 tools/boot_entry_probe.py --disk build/boot/udeks.d81 --drive 1581 \
  --output build/generic-apps/d81-typed-boot
flatpak run --command=c1541 net.sf.VICE -attach build/boot/udeks.d81 -list
```

VICE 3.10 and 1986 true-drive testing are distinct from physical 1581 testing;
the latter is still pending.
The checked-in `build/udeks.d64` / `.d71` release snapshots are not automatically
updated by `make boot`; `make publish-boot` now publishes all three explicitly.

Format references: [VICE D81 documentation](https://vice-emu.sourceforge.io/vice_17.html)
and Commodore's [1581 User's Guide, chapter 10](https://s3.amazonaws.com/com.c64os.resources/weblog/sd2iecdocumentation/manuals/1581_Users_Guide.pdf).
