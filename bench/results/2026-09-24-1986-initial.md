# Initial `1986` compiled-C results

Status: **preliminary, emulator-only, not an executive-CPU decision**.

These measurements prove the harness, timer, ownership handoff, result format,
and checksum validation. Three runs of each configuration produced identical
results. CIA1 Timer B supplied one-megahertz system ticks and its underflow flag
was checked for every case.

All three recorded Z80 runs used `double_z80_frequency = 0` and `tinker = 0`.
In `1986`, that selects two Z80 T-states per one-megahertz bus cycle—the stock
effective 2 MHz timing. As a control, the identical payload was run once with
the optional doubled-Z80 setting enabled. Every substantive tick count halved
exactly: fill 6,305; copy 7,841; checksum 3,487; control 5,538; and arithmetic
2,145. That control run is excluded from the result table and confirms that the
published Z80 column is not the 8 MHz daughterboard configuration.

| Case | Iterations | 8502 1 MHz | 8502 2 MHz | Z80 stock | 2 MHz 8502 / Z80 |
|---|---:|---:|---:|---:|---:|
| empty | 1 | 69 | 35 | 60 | — |
| fill | 128 | 37,516 | 18,758 | 12,610 | 1.49× |
| copy | 128 | 41,227 | 20,613 | 15,682 | 1.31× |
| checksum | 128 | 22,626 | 11,313 | 6,974 | 1.62× |
| control | 128 | 28,006 | 14,003 | 11,076 | 1.26× |
| 16-bit arithmetic | 64 | 28,260 | 14,130 | 4,290 | 3.29× |

Lower is better. The ratio column uses unadjusted total ticks; the empty-call
overhead is shown so later analysis can choose whether to subtract it.

For this small shared-C suite, SDCC's Z80 output is faster in every substantive
case even against cc65's 2 MHz 8502 output. The result is especially large for
16-bit arithmetic. The linked payloads also differ substantially: the 8502
image is 1,940 bytes including startup and selected runtime helpers, while the
Z80 link map reports 633 bytes of code. The Z80 `.bin` is an 8 KiB padded
transport window; that padding is not code size.

This does **not** establish that the Z80 is the better executive. The current
suite has no interrupt latency, full context switch, syscall dispatch, MMU
transition, VDC/VIC access, IEC path, or handoff-cost case. It has run only in
`1986`, not VICE or real hardware. It compares the selected size-oriented
compiler configurations, not handwritten assembly or other optimization modes.
