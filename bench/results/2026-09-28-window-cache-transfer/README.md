# Bank-crossing window-cache reference results

All eleven PRGs pass in 1986 and VICE (22 raw records). Cases 0–7 cover
168×104 at source/destination bit offsets 0/7 through 7/0. Case 8 is a
17×11 right-edge source, case 9 a 1×1 bottom-right pixel, and case 10 a
220×160 image. The independent per-pixel decoder requires exact equality
of all 8,000 shadow bytes and 32 dirty-page flags, complete success state,
cache-before/cache-after/capacity-boundary guards, kernel MMU profile,
synthetic service-page restoration, invalid-geometry rejection and zero
reserved bytes. Native 1986 provenance is tracked-clean revision
`39797864231dd0c52431df3ed9b4c724af2d19a9`; compiled input hashes were verified
unchanged across the run. No sibling emulator source was edited.

Raw record at `$7FC0`, 8,096 bytes:

| Offset | Content |
| --- | --- |
| 0–7 | `WCAC`, version 1, complete state 2, case, failure 0 |
| 8–11 | Paste CIA count, duplicated from 22–25 |
| 12–17 | Guards `$5A/$A5`, MMU `$3E`, service/validation flags 1/1, boundary `$C3` |
| 18–21 | Capture CIA timer ticks, little-endian |
| 22–25 | Paste CIA timer ticks, little-endian |
| 26–63 | Zero reserved bytes |
| 64–8063 | Final bank-0 shadow |
| 8064–8095 | Dirty-page flags |

Timers isolate capture and paste: background setup, service validation and
result copying are excluded. Runs disable display and mask IRQs at stock
1 MHz. Counts are primitive measurements, **not GUI latency**. The gateway
and synthetic service-page pattern are restored; real service execution,
active interrupts, worker/task interaction and screen commits are not tested.

VICE default-image capture takes 1,154,116–1,623,844 ticks; paste takes
1,939,409–2,758,923 ticks. The resized-image paste takes 5,186,369 ticks.
The C implementation is therefore too slow to ship as the fast-move fix,
even before compositor/screen-commit costs. Do not compare these isolated
counts directly with earlier end-to-end bounded-replay frame counts.

`report.json` is generated by `python3 tools/window_cache_bench.py decode`.
`SHA256SUMS` covers raw records, report and engine provenance. Exact PRGs
and sources are in the matching artifact directory. Production boot disks
are unchanged; next is a measured assembly byte-blitter prototype, followed
by explicit code placement and live-IRQ/compositor/input/hardware gates.
