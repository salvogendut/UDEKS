# ASM cache capture/paste qualification and C comparison

All eleven full-image cases plus the 66-check row matrix pass in each of
1986 and VICE (24 records). The original `WCAC` layout is unchanged; its
two timers isolate capture and paste. The matrix uses `WROW`, version 1,
complete state 2, failure 0, count 66 at offset 8, guards `$5A/$A5` at
12/13, and zero reserved bytes. Both record types contain all 8,000 final
shadow bytes and 32 dirty flags, independently compared per pixel.

Two additional negative-control records deliberately fail with code 3: capture
tail masking is replaced with three NOPs. Final valid pixels/dirty flags still
match, proving those alone cannot qualify zero padding in the packed cache.
The direct padding check detects the mutation in both engines, and the decoder
rejects each raw negative record. Mutation hashes and exact fault PRG are
preserved alongside the positive evidence, not counted as passing tests.

`report.json` records raw counts; `comparison.json` is generated by
`tools/window_cache_compare.py` against the immutable C reference. 1986
source fingerprints and VICE Flatpak build match that reference. Each engine
run manifest binds all twelve PRG hashes to the exact captured record hashes;
the preservation tool rejects stale/mixed records. No sibling emulator
changes were made.

VICE default-window paste decreases from 1,939,409–2,758,923 ticks to
325,486–593,322 ticks, a **4.56–6.87× speedup by paired case**. Resized
220×160 paste decreases from 5,186,369 to 968,935 ticks. Capture also improves.
At nominal 1 MHz default paste is roughly 0.33–0.59 seconds, but the tested
primitive has no active display or IRQs. Screen commits, old-background
restoration, chrome, window composition, input and cancellation are excluded.
These are **not end-to-end drag-release or real-hardware results**.

The faster code borrows the synthetic service page for the entire operation,
restoring once at the end, instead of the C reference restoring per row.
The prototype must not yield, call services or nest drawing inside that lease.
Real-service survival, live IRQs, serialized ownership and a bounded-input
continuation remain gates before resident integration.

Exact programs, maps and sources are in
`bench/artifacts/2026-09-28-window-cache-asm/`. Their 1,023-byte object code/state
still exceeds the 49-byte raster reserve by 974 bytes before manager bindings.
Production boot disks are unchanged. Next is explicit graphics-service
placement and bounded lease integration, not a premature hardware boot test.
