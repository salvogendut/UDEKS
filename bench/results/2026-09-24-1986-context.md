# Initial `1986` task-context results

Status: **preliminary, emulator-only, not an executive-CPU decision**.

Three runs per configuration produced identical results. Each variant contains
eight samples of 64 save/restore operations. Register and runtime-state
qualification passed before timing, no timer overflow occurred, and matching
empty-loop samples were subtracted individually.

| Context contract | 8502 1 MHz | 8502 2 MHz | Z80 stock |
|---|---:|---:|---:|
| CPU core | 48 | 24 | 116 |
| compiler-complete | 412 | 206 | 116 |
| full admitted architecture | 412 | 206 | 180 |

Values are one-megahertz system ticks per save/restore operation; lower is
better.

## Context contracts

The 8502 CPU frame contains call-stacked PC, P, A, X, Y, and a saved hardware
SP, for seven bytes per task. Arbitrary cc65 preemption additionally requires
all 26 bytes declared by cc65's `zeropage.inc`: its software-stack pointer,
secondary register, pointer and temporary slots, and six-byte register bank.
The resulting compiler-complete and full contexts are 33 bytes, excluding the
separate C stack and inactive hardware-stack allocation.

The 8502 copy is fully unrolled because this mechanism is a kernel hot path.
It requires 206 ticks at 2 MHz. Its CPU-only frame is much cheaper at 24 ticks,
showing that the cc65 runtime—not the processor register set—dominates the
context cost.

The SDCC-complete Z80 context contains primary AF/BC/DE/HL, IX, IY, call-stacked
PC, and saved SP: 16 bytes and 116 ticks. The full UDEKS application context
also admits AF'/BC'/DE'/HL', producing 24 bytes and 180 ticks. I, R, IFF, and
interrupt mode remain kernel-global under this provisional ABI.

## Interpretation

The stock Z80 wins compiler-complete context transfer by 90 ticks and uses 17
fewer context bytes than the 2 MHz 8502. When the complete alternate register
bank is admitted, the Z80 retains a smaller 26-tick and nine-byte advantage.
Conversely, the 8502 CPU-only mechanism is 4.83 times cheaper than the Z80
primary-register path.

This counterbalances the interrupt-service suite: the 8502 has substantially
cheaper interrupt handling, while the Z80 has cheaper practical task-context
transfer and faster compiled-C workloads. These results must not simply be
added because the interrupt suite includes different instrumentation and entry
contracts. A production preemption prototype is required after the task ABI is
selected.

The benchmark stores and reloads the same context rather than running a full
scheduler. This has the transfer cost of saving one runnable task and restoring
another, but excludes task selection, MMU changes, stack relocation, cacheless
code/data locality effects, and policy. Emulator agreement and real hardware
remain required.
